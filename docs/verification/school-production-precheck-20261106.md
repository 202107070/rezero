학교 체크아웃과 작업 기준 develop `71c667e`의 파일 차이는 RoomHeader, RoomPage, ResultPage 3개다. 이들 변화는 기존 develop의 방 번호 표시·결과창 이동 수정이며 작업 브랜치에 포함돼 있다. 캐릭터/디자인/DB 설치 파일의 별도 변경을 덮어쓰는 차이는 발견하지 않았다. package.json, 추적된 package-lock.json, 운영 DB 설치 SQL과 config는 적용 후보와 동일하다. 학교의 **미커밋** lock 변경은 별개이므로 원본 폴더에서 checkout/reset/install하지 않는다.

## 적용 전 반드시 준비할 사항

1. 원본 폴더의 미커밋/미추적 파일과 비공개 환경설정, 운영 DB·Valkey를 학교 서버 안의 제한된 백업 디렉터리에 보관한다. 백업 내용과 비밀번호를 문서/로그/Git에 넣지 않는다.
2. 별도 버전 디렉터리에 적용 커밋을 준비하고 프론트/백엔드 버전을 함께 고정한다. 원본 운영 폴더와 분리 테스트 환경은 보존한다.
3. **기존 기동 동작을 검토한다.** `backend/bin/www` → `connectRedis()` → `clearAllPersistedChatMessages()`가 `room:*:messages`, `chat:room:*:recent` 키를 삭제한다. 데이터 보존 조건을 지키려면 이 정리를 실행하지 않는 기동 경로를 준비해야 한다. 이번 점검에서는 해당 함수를 호출하지 않았다.
4. 기동·종료·복구 방법과 로그 위치를 준비한다. 확인된 진행 중 경기는 없지만 실제 기동 직전에 다시 조회한다.
5. 적용 후 내부 health → 외부 HTTP/Socket → 두 계정 전체 게임 흐름 → 서버 로그/DB 결과 순서로 검증한다. 외부 접근에 방화벽 조정이 실제로 필요한 경우 승인된 Tailscale 접근 범위만 사용한다.

사전 점검 완료는 운영 배포 완료를 뜻하지 않는다. 백업, 운영 기동, 외부 연결, 운영 주소에서의 전체 게임 검증은 아직 남아 있다.

 0. 공통 사항
================================================================================

[프로젝트 한 줄 요약]
  레트로 픽셀 UI의 실시간 코딩 배틀 게임. React SPA + Electron 데스크톱.
  앱 제목: "Rocky 배틀 로비 - RETRO ARCADE"

[기술 스택]
  React 19, TypeScript, Vite, React Router 7, Electron

[라우트 (src/constants/routes.ts)]
  /login      → 로그인·회원가입 (앱 시작 화면, GuestRoute)
  /           → 로비 (ProtectedRoute)
  /room       → 대기실 (ProtectedRoute)
  /battle     → 배틀 (ProtectedRoute)
  /result     → 결과 (ProtectedRoute)
  /practice   → 연습 (ProtectedRoute)
  /build      → 빌드 (ProtectedRoute)

[페이지 vs 컴포넌트 역할 분리]
  pages/     : 라우트에 1:1 대응. 상태·이벤트·navigate·store/서비스 호출 담당 ("컨트롤러")
  components/: UI 렌더 + props 콜백으로 상위에 입력 전달 (가능한 한 상태 없음)

[모달 공통 패턴]
  open=false → null (안 그림)
  바깥(overlay) 클릭 → 흔들림만, 닫히지 않음
  modal-content 클릭 → stopPropagation
  폼 오류 → modal-shake-error 클래스

[데이터 저장 — DB 연동 준비 중]

  게임 세션·프로필은 앱 실행 중 메모리 store 로 유지한다.
  계정 목록만 localStorage (rezero_auth_accounts) 에 저장한다.
  로그인 세션(currentUser)은 메모리 only — 앱 재실행 시 /login 으로 복귀.

  ┌─────────────────────┬──────────────────────────────────────────────┐
  │ authService         │ 계정 localStorage + 세션 메모리 (로그인 상태)   │
  ├─────────────────────┼──────────────────────────────────────────────┤

 0.5 로그인·회원가입 (Auth)
================================================================================

--------------------------------------------------------------------------------
 0.5.1 개요
--------------------------------------------------------------------------------

로그인 화면은 ROUTES.LOGIN = '/login' 이다. 앱 최초 진입·재실행 시 여기서 시작한다.
인증 후에만 로비·대기실·배틀 등 게임 화면에 접근할 수 있다 (ProtectedRoute).

[계정 이용 방법]
  1) 내장 테스트 계정 — 화면에 표시하지 않음. 수동으로 아이디·비밀번호 입력.
       testuser1 / test1234
       testuser2 / test1234
  2) 개인 회원가입 — [회원가입] 탭에서 아이디·비밀번호·닉네임 입력 후 가입.
       가입한 계정은 localStorage 에 저장되며, 이후 [로그인] 탭에서 동일 아이디로
       로그인할 수 있다.

[흐름]
  앱 시작 → AuthProvider.initAuth() → currentUser = null → /login
  로그인 또는 회원가입 성공
    → authService 가 currentUser 설정
    → initializeUserSession() (테스트 로드아웃 등)
    → navigate('/') 로비
  로그인 상태에서 /login 접근 → GuestRoute 가 / 로 리다이렉트
  앱 종료 후 재실행 → 세션 소멸 → 다시 /login (계정 데이터는 localStorage 유지)

 1. 로비 (Lobby)

--------------------------------------------------------------------------------
 1.1 개요
--------------------------------------------------------------------------------

로비는 ROUTES.LOBBY = '/' 이다. 로그인 후 진입하는 메인 화면이다.
플레이어가 여기서:

  - 방 목록을 보고 필터링·페이지 이동·입장 (처음엔 빈 목록)
  - 새 방 생성 후 대기실(/room)로 이동
  - 연습 모드(/practice) 설정 후 시작
  - 로비 채팅 (현재 로컬 mock, 서버 없음)
  - 프로필·칭호·매치 스토리(코드 히스토리) 확인
  - 골드·배틀 아이템 인벤토리·룰렛
  - 온라인 유저 목록 / 랭킹 탭 (현재 로그인 유저 본인만 표시)
  - 설정(화면 모드, BGM) 및 앱 종료

를 수행한다.

 2.1 개요
--------------------------------------------------------------------------------

대기실은 ROUTES.ROOM = '/room' 이다. 로비에서 방 생성·입장 시 URL 쿼리로 설정값을
받아, 플레이어가 배틀 시작 전에 준비하는 공간이다.

플레이어가 여기서:

  - 플레이어 슬롯 확인 (호스트 / 빈 슬롯 / 상대)
  - 캐릭터 선택, 배틀 설정(언어·난이도·문제 수) 확인

  - 대기실 채팅 (로컬 mock)
  - 호스트: [START] 로 배틀 시작 / [로비] 로 나가기
  - 비호스트: READY 토글 / [로비] 로 나가기
  - (선택) 프로필 클릭 → 강퇴 (호스트만)

를 수행한다.

현재는 멀티플레이 API·소켓 없이 단일 클라이언트 mock 이다.
SOLO_START_BYPASS = false 이므로 인원·READY 조건을 만족해야 START 가능하다.
1:1 모드에서는 호스트가 [봇 초대] 로 상대를 추가한 뒤 시작할 수 있다.

--------------------------------------------------------------------------------
 3.7 문제 capabilities (정책 기반)
--------------------------------------------------------------------------------

  [원칙]
    문제 데이터에는 type, visual, capabilityOverrides 만 저장
    BattlePage·PracticeProblemViewer 는 resolveProblemCapabilities() 결과만 사용

  [동작 방식]  (플래그 변수로 분기하지만, 플래그는 매번 계산)
    문제 JSON에 hasVisual 같은 boolean 을 넣지 않는다.
    type·visual·(선택) capabilityOverrides 와 gameMode 를 넣으면
    resolveProblemCapabilities() 가 currentCaps 를 만들어 준다.

      type + visual + capabilityOverrides + gameMode
              ↓
      resolveProblemCapabilities()
              ↓
      currentCaps  … hasVisual, hasImage, showCodePanel, items.* 등

    화면은 currentCaps 만 참조한다. BattlePage 에서 useMemo 로 문제가 바뀔 때마다 갱신.
      보기 영역     shouldRenderProblemVisual = hasVisual || hasImage
      문제 패널     showCodePanel / showMultipleChoicePanel / showShortAnswerPanel
      아이템 버튼   disabled = !canUseItem(currentCaps, itemKey)

    정책 원본은 constants/problemCapabilityPolicy.ts (STYLE_ITEM_POLICY).
    특수 문제만 capabilityOverrides 로 아이템 허용을 덮어쓸 수 있다.

  [파일]
    constants/problemCapabilityPolicy.ts   STYLE_ITEM_POLICY
    utils/problemCapabilities.ts           resolveProblemStyle, resolveProblemCapabilities, canUseItem
    utils/problemVisualUtils.ts            hasRenderableVisual, problemHasVisual

  [스타일 매핑]
    code              ← fill_blank, visual_fill_blank
    short_answer      ← short_answer
    multiple_choice   ← multiple_choice

  [아이템 정책 — gameMode === 'item']
    code            힌트(revealLength·revealPrev), blankBreak, buildCharge + 공격 전부
    short_answer    힌트만, blankBreak·buildCharge 불가, 공격 허용
    multiple_choice 자기 버프 전부 불가, 공격 아이템만 허용
    normal 모드     items 전부 false

  [BattlePage]
    currentCaps = resolveProblemCapabilities(currentProblem, { gameMode })
    shouldRenderProblemVisual = hasVisual || hasImage
    아이템 버튼 disabled = !canUseItem(currentCaps, itemKey)
    패널 표시: showCodePanel / showMultipleChoicePanel / showShortAnswerPanel
